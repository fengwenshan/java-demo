# GitHub Actions 构建与私有配置

## 触发方式

工作流文件在**仓库根目录**：

```
.github/workflows/scope-ftp.yml
```

因为项目位于仓库子目录 `07_scope-ftp/`，工作流必须放在仓库根的 `.github/workflows`，不能放在项目目录里。

触发条件：

- push 到 `main`，且改动 `07_scope-ftp/**` 或工作流本身
- Pull Request 改动上述路径
- 在 Actions 页面手动 `Run workflow`（`workflow_dispatch`）

## 构建产物

| Job / Artifact | 内容 |
| --- | --- |
| `ScopeFTP-server-jar` | `ScopeFTP-server-1.0.0.jar` |
| `ScopeFTP-server-profiles` | `ScopeFTP-server-{default,xiaoshan,xihu}.zip`（私有配置齐全时） |
| `ScopeFTP-client-macos-arm64` | Apple Silicon DMG |
| `ScopeFTP-client-macos-x64` | Intel Mac DMG |
| `ScopeFTP-client-windows-x64` | Windows x64 NSIS 安装包 `.exe` |

产物在对应 Actions run 页面底部 Artifacts 区域下载，不需要本地打包。部署时把 `ScopeFTP-server-*.jar` 放到 `server/target/` 或设置 `JAR_PATH`，再运行 `./deploy/deploy.sh remote`。

## 私有配置文件

以下文件只保留在本地，**不要提交**：

```
server/src/main/resources/application-default.yml
server/src/main/resources/application-xiaoshan.yml
server/src/main/resources/application-xihu.yml
```

它们已写入 `07_scope-ftp/.gitignore`。如果之前误加入过 Git，执行：

```bash
git rm --cached 07_scope-ftp/server/src/main/resources/application-*.yml
```

## 配置 GitHub Secrets

进入 GitHub 仓库：`Settings → Secrets and variables → Actions → New repository secret`。

### 1. 服务端 profile 配置

在本地把 YAML 转成单行 base64：

```bash
cd 07_scope-ftp
base64 -i server/src/main/resources/application-default.yml | tr -d '\n'   # macOS
# Linux: base64 -w0 server/src/main/resources/application-default.yml
```

分别保存为：

- `APPLICATION_DEFAULT_YML_BASE64`
- `APPLICATION_XIAOSHAN_YML_BASE64`
- `APPLICATION_XIHU_YML_BASE64`

工作流会在测试/打包前把这些内容还原成对应的 `application-*.yml`，构建完成后丢弃，不会进入 Git。

三个 Secret 缺任意一个时：

- 服务端 Jar 和客户端仍会构建；
- 分环境部署包跳过（Actions 日志会出现 warning）；
- 不会用空配置硬打包。

### 2. 客户端内置凭据（可选）

不配置时客户端使用编译期内置的演示默认值；生产环境建议配置：

- `UPLOAD_CLIENT_APP_KEY`
- `UPLOAD_CLIENT_APP_SECRET`
- `UPLOAD_CLIENT_SERVER_URL`

工作流只在 Secret 非空时把它们注入 Tauri 的 Rust 编译环境，不会写入源码或配置文件。

## 服务端与客户端密钥配合

服务端启动时未指定密钥，使用 `application.yml` 里的内置演示默认值。可以启动 Jar 时直接指定，也可以用环境变量：

```bash
# 默认内置 demo-app / demo-secret-...
java -jar ScopeFTP-server-1.0.0.jar

# 直接启动 Jar 时指定（--app-key/--app-secret 会映射到第一个预配发客户端）
java -jar ScopeFTP-server-1.0.0.jar --app-key my-key --app-secret my-secret

# 本地脚本 / 环境变量同样生效
./scripts/run-server.sh --app-key my-key --app-secret my-secret
UPLOAD_APP_KEY=my-key UPLOAD_APP_SECRET=my-secret ./scripts/run-server.sh
```

客户端在「设置」里填同样的 AppKey/AppSecret；留空则使用客户端内置默认值。

客户端每台服务器都有可选的 `AppKey` / `AppSecret` 输入：

- 留空：使用客户端内置默认值；
- 填写：使用该服务器自己的值；
- 已保存的自定义 AppSecret 显示为掩码，保持不动保存会保留原 secret；
- 点输入框右侧的清除按钮再保存：恢复内置默认值。

服务端和客户端的 AppKey/AppSecret 必须一致，否则验证连接会返回认证失败。
