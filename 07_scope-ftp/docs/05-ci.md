# GitHub Actions 构建与私有配置

## 触发方式

工作流文件在**仓库根目录**：

```
.github/workflows/scope-ftp.yml
```

因为项目位于仓库子目录 `07_scope-ftp/`，工作流必须放在仓库根的 `.github/workflows`，不能放在项目目录里。

触发条件：

- **只有 push `v*` tag 才触发构建**
- 普通 `main` push、Pull Request、手动发布 GitHub Release 都不会触发
- tag 构建完成后自动创建/更新 GitHub Release

## 构建产物

| Job / Artifact | 内容 |
| --- | --- |
| `ScopeFTP-Server-package` | `ScopeFTP-Server.zip`（默认包，内部固定 `ScopeFTP-Server/` + `ScopeFTP-Server.jar` + `start.sh` + `scop-ftp.env`）；私有配置齐全时额外有 `ScopeFTP-Server-xiaoshan.zip` / `ScopeFTP-Server-xihu.zip` |
| `ScopeFTP-macos-arm64` | Apple Silicon DMG + `.app.tar.gz` 更新包 + `.sig` |
| `ScopeFTP-macos-x64` | Intel Mac DMG + `.app.tar.gz` 更新包 + `.sig` |
| `ScopeFTP-client-windows-x64` | Windows x64 免安装 `ScopeFTP.exe` + NSIS 安装包 `.exe` + `.nsis.zip` 更新包 + `.sig` |

产物在对应 Actions run 页面底部 Artifacts 区域下载，不需要本地打包。部署时解压 `ScopeFTP-Server.zip`，把其中的 `ScopeFTP-Server/ScopeFTP-Server.jar` 放到 `server/target/` 或设置 `JAR_PATH`，再运行 `./deploy/deploy.sh remote`。

## 发布到 GitHub Releases

只有推送 `v*` tag 才会构建并发布：

```bash
git tag v1.0.0
git push origin v1.0.0
```

普通 `main` push、PR、手动创建/发布 Release 都不会触发构建。

工作流会等服务端、macOS 客户端、Windows 客户端全部构建成功后：

- 创建或更新同名 GitHub Release（`tag_name` 为 tag 名）
- 自动生成 release notes
- 上传构建产物：
  - 默认部署包：`ScopeFTP-Server.zip`（内部固定 `ScopeFTP-Server/` + `ScopeFTP-Server.jar` + `start.sh` + `scop-ftp.env`）
  - 分环境包：`ScopeFTP-Server-xiaoshan.zip` / `ScopeFTP-Server-xihu.zip`（内部同样固定；私有配置不齐时没有）
  - macOS DMG（ARM64 / Intel）
  - Windows 免安装 exe + NSIS 安装包
  - 三平台 Tauri updater 更新包（`.app.tar.gz` / `.nsis.zip`）及对应 `.sig`
  - `latest.json`（自动更新清单，客户端从 latest release 的固定地址读取）

Release 资产来自本次 run 的 artifacts，因此不需要再手动下载上传。发布需要工作流具备 `contents: write` 权限，`release` job 已单独声明。

## 私有配置文件

所有环境文件只保留在本地，**不要提交**（dev / docker / xiaoshan / xihu）：

```
server/src/main/resources/application-dev.yml
server/src/main/resources/application-docker.yml
server/src/main/resources/application-xiaoshan.yml
server/src/main/resources/application-xihu.yml
```

它们（以及任何 `application-*.yml`）已被 `07_scope-ftp/.gitignore` 过滤；仓库只入库 `application.yml`，
它自带可独立启动的默认值，缺少环境文件也能打包、启动。

如果之前误加入过 Git，执行：

```bash
git rm --cached 07_scope-ftp/server/src/main/resources/application-xiaoshan.yml
git rm --cached 07_scope-ftp/server/src/main/resources/application-xihu.yml
```

## 配置 GitHub Secrets

进入 GitHub 仓库：`Settings → Secrets and variables → Actions → New repository secret`。

### 1. 服务端生产环境配置

在本地把 YAML 转成单行 base64：

```bash
cd 07_scope-ftp
base64 -i server/src/main/resources/application-xiaoshan.yml | tr -d '\n'   # macOS
# Linux: base64 -w0 server/src/main/resources/application-xiaoshan.yml
```

分别保存为：

- `APPLICATION_XIAOSHAN_YML_BASE64`
- `APPLICATION_XIHU_YML_BASE64`

工作流会在测试/打包前把这些内容还原成对应的 `application-*.yml`，构建完成后丢弃，不会进入 Git。

两个 Secret 缺任意一个时：

- 服务端默认部署包 `ScopeFTP-Server.zip` 和客户端仍会构建；
- 分环境部署包跳过（Actions 日志会出现 warning）；
- 不会用空配置硬打包。

### 2. 客户端内置凭据（可选）

不配置时客户端使用编译期内置的演示默认值；生产环境建议配置：

- `UPLOAD_CLIENT_APP_KEY`
- `UPLOAD_CLIENT_APP_SECRET`
- `UPLOAD_CLIENT_SERVER_URL`

工作流只在 Secret 非空时把它们注入 Tauri 的 Rust 编译环境，不会写入源码或配置文件。

### 3. 客户端自动更新签名（必须）

自动更新包必须由 Tauri 更新密钥签名，**未配置时客户端构建会直接失败**，不会发布可被伪造的更新包。

本地已生成密钥（不要提交私钥）：

```
07_scope-ftp/client/.tauri/scopeftp.key       # 私钥，权限 0600
07_scope-ftp/client/.tauri/scopeftp.key.pub   # 公钥，已写入 tauri.conf.json
```

在仓库 `Settings → Secrets and variables → Actions` 添加：

- `TAURI_SIGNING_PRIVATE_KEY`：`scopeftp.key` 文件的完整内容。
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`：生成时设置的密码；本密钥无密码，不需要添加。

客户端 `src-tauri/tauri.conf.json` 里的 `plugins.updater.pubkey` 必须与 `scopeftp.key.pub` 对应。
私钥丢失后无法再给已安装客户端签名升级包，务必离线备份。

发布 tag 前确认：

```bash
# tag 与客户端版本一致
node -p "require('./07_scope-ftp/client/src-tauri/tauri.conf.json').version"
# v1.0.3 发布时输出 1.0.3
```

## 服务端与客户端密钥配合

服务端启动时**必须**指定密钥，没有内置默认值，缺失时直接启动失败。可以启动 Jar 时直接指定，也可以用环境变量或**当前环境文件**（`application-<env>.yml`）：

```bash
# 必须提供凭证（环境变量 / --app-key / --app-secret / 环境文件 任一来源）
UPLOAD_APP_KEY=my-key UPLOAD_APP_SECRET=my-secret ./scripts/run-server.sh

# 指定环境（docker / xiaoshan / xihu；dev 为默认，不传 --env）
./scripts/run-server.sh --env xiaoshan --app-key my-key --app-secret my-secret

# 直接启动 Jar 时指定（--app-key/--app-secret 会映射到第一个预配发客户端）
java -jar ScopeFTP-server-1.0.0.jar --spring.profiles.active=xiaoshan --app-key my-key --app-secret my-secret
```

客户端在「设置」里必须填同样的 AppKey/AppSecret（必填，留空无法保存/验证）。每台服务器都有必填的 `AppKey` / `AppSecret` 输入：

- 必填，必须与服务端启动时指定的一致；
- 已保存的自定义 AppSecret 显示为掩码，保持不动保存会保留原 secret；
- 不再回退客户端内置默认值（清空后保存会被拒绝）。

服务端和客户端的 AppKey/AppSecret 必须一致，否则验证连接会返回认证失败。
